# Architecture

Mallside is a static browser application. `dist/` contains the editable HTML, CSS and ES modules as well as the deployable assets. It is not generated by an untracked build. Node's standard library runs tests and release checks; Python's standard library provides the development server. The same-repository Pages workflow uses pinned esbuild to create a minified production artifact; see DEPLOYMENT.md.

The runtime uses vendored Three.js r180. Bundled relative asset/module URLs let the same `dist/` run at `/` or the GitHub Pages `/Mallside/` prefix. Do not introduce origin-root `/assets/...` or `/app.js` paths. Module version query strings are cache keys, not a mandatory deployment version schema. The GitHub migration changes packaging metadata and adds rights links in the menu/footer. The current UI entry uses `app.js?v=36.0.0`; changed module imports share their new cache keys while unchanged modules retain earlier keys. The production artifact bundles these into one content-hashed script.

## State and saves

The UI owns a normalized engine state and remembers unpaid selections before saving. Browser local storage holds career and free-shop saves separately. Returns use game receipts and game rules; no real merchandise purchase or refund occurs. State changes should go through the engine functions and maintain their tested invariants. A paid purchase should not be duplicated by reloading, and ambient NPC shopping must not alter player money or stock.

Primary keys remain `mallside-career` and `mallside-free`, containing the original version-6 JSON. `engine.parseSave` validates critical progression before using the existing migrations (versions 1–6); strict normalization throws instead of returning a new game. The original permissive `loadState` API remains available to existing callers. Optional appearance and later feature fields retain their established normalization.

`save-storage.js` reads both slots before any write. A valid existing primary seeds a missing/unusable backup without changing primary bytes. Normal writes first capture the prior validated primary in the mode’s `-backup` envelope (format/version/mode/time/raw JSON/FNV-1a checksum), then write the next primary. Unchanged snapshots do not rotate backups. A failed backup write leaves the primary untouched; a failed primary write leaves a usable prior copy. The checksum detects accidental backup changes, not malicious edits. No multi-key transaction is claimed.

Unreadable or missing-with-backup primaries block autosaves; the app displays an exclusive paused recovery view. Explicit replacements recheck the reviewed raw primary and backup before committing. Healthy pre-restore progress becomes an undo backup; damaged primary data never replaces a good backup. Save attempts compare the loaded primary with current storage, and storage events pause a stale tab. This is best-effort conflict protection, not cross-tab transactional synchronization. First-time empty modes can start normally, while retrying recovery after data disappears still requires explicit fresh-start confirmation.

Portrait binaries live separately in IndexedDB. JSON save exports preserve game state but do not contain those image binaries. A new hosting origin starts with separate storage; use reviewed JSON export/import to move progression. Never add automatic uploading of saves without an explicit product decision and privacy review.

## Scene and fitting resources

Mall and wardrobe use the same anatomical rig and merchandise fit rules. Geometry/texture caches share immutable templates; individual actors own skeletons and mutable fitting resources. Pose previews restore the equipped outfit when closed. Scene changes must cancel animation loops and release owned WebGL resources without disposing shared templates.

The character is retargeted from CC0 source geometry. Fabric posing and constrained bag straps are controlled game deformations rather than a complete cloth-physics system. Existing coverage masks and fit tests cover the reviewed motion cases, not every imaginable product/body combination.

## Data and permissions

`product-photos.js` is the runtime index; the older `assets.json` is a retained historical subset. Do not treat the older JSON as the full current catalog. Catalog branch IDs can reuse one real model and photo. `docs/ASSET_INVENTORY.json` records photo provenance and hashes without asserting copyright clearance. Updating a product/photo requires both identity verification and a rights review.

No backend, database credentials or payment integrations are required. The browser fetches local modules/images and remote Google Fonts, and opens external product references only when a player follows a link.

The collection room reuses the studio renderer and the exact owned-product models. Starter sleeves use shared indexed material groups, without duplicating anatomical meshes or modifying the garment fit envelope. Prepared outfits and guestbook pages are bounded optional version-6 save records; applying a planned look validates every purchase before changing equipment. The room and guestbook have no separate backend.

The v27 neighborhood module owns bounded daily notice/property/home records. Validation happens before advancing time or granting XP; activity props never enter purchases. Five local chapters retain the original first three history records. The room studio moves through named furniture-safe paths without changing mall position, and shelf order stays in the existing display ID array. Floor detail uses a disposable 64×64 procedural texture with no external assets.

The v29 `input-controls.js` module owns directional-pad press/release timing and cleanup. Short presses step through the same collision resolver; holds use the existing continuous movement path. Pointer IDs prevent a second finger from ending an active gesture, and cancel/lost-capture/blur/hidden events stop without a step. World keyboard movement requires canvas focus and rejects modified/composing events. Views dispose their pad listeners before replacing DOM. Keyboard focus is revealed above/below fixed navigation without smooth-scroll delays; pointer input keeps its normal scrolling behavior. Dialogs and journey overlays share background inertness, including the skip link; map drawers remain nonmodal with explicit focus return. Responsive controls live beside/below the canvas rather than obscuring it.


The v30 companion modules own ten original conversation activities after completed local stories. `companion-content.js` contains prompts, answer responses and original-choice callbacks; `companion-life.js` validates a single optional active visit and the latest 30 completed memories; `companion-ui.js` renders invitations, saved choices and rereadable replies. Normalization runs after local stories so invalid optional companion data cannot invalidate older valid progress. Finishing checks the original mall, both answers, the shared daily limit and closing time before advancing time, granting XP or recording a memory. It uses the existing daily friendship bond and level-up functions. Choices alone grant no time, money or rewards. No catalog props, photo assets, primary save keys or backup format change.


The v31 play shell separates the scene, movement rail and shopping sidebar. `play-ui.js` renders filtered real-store destinations, shopping guidance and interactive map links. Drawers live outside the canvas container so short landscape scenes cannot clip their scrollable results. Store transition callbacks refresh the guide without replacing controls every frame. Shop exits and manual route cancellation discard pending multi-floor steps; court-map routes leave interiors before using campus coordinates. Frame movement ignores coordinate jumps when the layout changes. `walkingStep` integrates exponential acceleration independently of refresh rate with immediate release; camera position and look target use time-based damping. Expanded play fixes the shell to the viewport and retains native fullscreen detection and a visible exit. The unified menu provides all major pages and compact-screen camera controls. New gallery details use shared instanced geometry and locally generated floor diagrams; no remote or newly sourced product imagery is introduced.

Document scrolling is immediate during view changes and focus reveal. This prevents queued smooth-scroll animations from moving a control after a navigation or scroll-to-focus operation, observed with native Safari input on the long Journal page. Player/camera smoothing is handled independently in the world math.

`canvas-size.js` coalesces ResizeObserver notifications into the next animation frame. World destruction disconnects the observer and cancels pending work, preventing Safari layout-feedback notifications when the canvas backing store changes during a resize.

The primary stylesheet has no remote font import. The app appends an optional print-media font stylesheet after initialization and enables it only when loaded, so local interface startup and default fonts do not depend on the font service responding.

`render-compat.js` guards and inlines r180’s identity ambient-light call in the shared shader chunk before mall/studio rendering. It avoids an observed Safari Metal address-space linker error without changing the lighting equation. It is idempotent and refuses an unrecognized helper body, so a future library upgrade cannot silently receive the same rewrite. Vendored library files remain unchanged.

## v33 rendering and presentation

`scene-finish.js` owns original HDR environment pixels/PMREM lighting, cached color and data textures, shared architectural bevels, camera composition and instanced route/contact accents. Environment render targets and finish textures belong to the scene; person teardown retains shared textures. Removed actors are pruned from contact tracking. Texture orientation and color/data spaces have numerical regressions.

Camera mode, guide visibility and incidental activity captions are normalized optional preferences in schema 6. World cutaways ease toward their target height; the close shop view includes a nonnavigable exterior floor/threshold and keeps the player in frame. Route samples follow existing waypoint segments and clear when the route ends. Starter clothing uses shared original shells and masked arm skin; researched retail garments retain their existing fitting path.

## v34 public places, shop options and motion

`furnishCampus` places water/notice waystations with physical colliders, protected approaches and clear walking spines. `fixtureStop` is the shared interaction resolver for physical fixtures and center-map routing. These stations use existing amenity/neighborhood transactions, preserving cooldowns and once-only invitation rewards. `court-life.js` owns a bounded set of original seated ambient visitors and respects crowd/reduced-motion settings.

`shop-options-ui.js` supplies research-only collection guides and bookmark controls. Optional `savedShops` IDs normalize/deduplicate/cap at 80 in the existing schema-6 state; toggling a bookmark changes no money, time or stock. Pending-shop physical counters/fitting controls resolve to information/associate interactions. The original information gallery follows existing fixture/collider positions.

`locomotionWeight` eases only the rig pose, independently of avatar input/position. Actual-distance gait retains two-bone foot solving. World, store customers/staff and collection-room previews pass frame deltas to pose updates; contextual arm/head gestures remain static under reduced motion.

## Original district activities (v35)

`district-life.js` supplies original dining menus, bounded dining history and one sketch per mall floor/day. The engine injects existing economy/time/recovery functions; no catalog stock or merchant evidence changes. `district-ui.js` renders review screens and the sketchbook. A dining route carries its store/meal ID in the destination, so cancellation, scene teardown or reload cannot leave a pending paid order. The controller validates the actual branch interior (or the branch door in lightweight mode) at arrival before charging. `mall-design.js` reserves each sculpture’s footprint and approach before additional furniture; map and physical stops share `fixtureStop`.

Character hand IK caches the solved quaternions only when the root-local target and full local chain inputs match. Semantic arm transitions blend from the previous rendered pose; reduced-motion callers retain exact immediate poses. Ambient visitors only relocate while outside the nearby seating region.

## Shopping lounges and ambient motion (v36)

`shopping-plans.js` keeps optional bounded shortlists, validates real local product identities and estimates current per-line game tax. It never charges, reserves inventory or alters catalog status. `shopping-plan-ui.js` renders drafts, explicit saves and actual-shop routes. The controller preserves focus/scroll across updates and discards unsaved draft edits on reopening. `planning-lounge.js` fills the existing six display footprints with original planning props and tags stations for category, budget and route views; a reserved bench uses existing rest rules.

`ambient-motion.js` supplies deterministic spaced spawn searches, bounded navigation-aware sidesteps, arrival speed and smooth sitting/bench targets. `character-rig.js` eases head orientation while reduced-motion and delta-zero callers keep exact poses. Scene telemetry records initial crowd clearance and seated blend for repeatable native checks.
